Social Media Monitoring System
Content Authenticity, AI Detection & Context Verification Module
Version

v1.0 — Proposed Feature Specification

Purpose

The existing system collects social-media/news content from:

X
Facebook
Reddit
Google News

The new requirement is to determine how trustworthy/authentic the collected content appears to be.

This feature should answer three different questions:

Was the text likely generated by AI?
Was the attached image/media likely generated or modified by AI?
Is the actual claim/content supported by available evidence, or does the context suggest that it is misleading/false?

These must be treated as three separate analyses.

1. Important Concept

The system must not treat “AI-generated” and “fake” as the same thing.

For example:

“IIUI will remain closed tomorrow because of heavy rain.”

This could be:

Case A

Human-written + true

Case B

AI-generated + true

Case C

Human-written + false

Case D

AI-generated + false

Therefore:

AI Detection
      ≠
Truth Verification

The system should report both independently.

Example:

Text AI likelihood: 82%
Image AI likelihood: 12%

Context verification:
SUPPORTED

Overall:
Likely AI-assisted content, but the claim appears credible.

That distinction is extremely important for the project.

3. Feature 1 — AI-Generated Text Detection
Objective

Estimate whether the textual content of a post appears to have been generated or heavily assisted by an AI model.

Examples:

Post:
"Dear students, please be informed that..."

AI likelihood:
78%

The system should not simply return:

AI = TRUE

Instead, use probabilistic results.

Recommended output
Likely AI-generated
Possibly AI-generated
Likely human-written
Insufficient evidence

Along with:

confidence_score: 0-100
4. Text Detection Pipeline
Collected Post
      ↓
Extract text
      ↓
Language detection
      ↓
Text preprocessing
      ↓
Minimum-length check
      ↓
AI detection model
      ↓
Confidence calculation
      ↓
Classification
Important preprocessing

The system should consider:

English
Urdu
Roman Urdu
mixed Urdu/English
hashtags
mentions
emojis
URLs
repeated text
very short posts

For example:

"OMG 😭😭 uni band ho gai??"

should not receive the same treatment as:

"Due to the prevailing weather conditions, the university administration has decided..."

Short social-media text generally provides much less evidence for reliable authorship classification.

5. Minimum Text Threshold

The system should not force an AI classification when there isn't enough text.

For example:

"Wow!"
"Breaking!"
"LOL"
"IIUI 😭"

should return:

Insufficient evidence

rather than:

Human-written: 91%

This is important because a detector can become misleading when given extremely short text.

6. AI Text Detection Result

Recommended internal structure:

{
  "ai_text": {
    "status": "likely_ai",
    "score": 82,
    "confidence": 0.82,
    "language": "en",
    "text_length": 247,
    "reason": "The text contains patterns associated with generated/formal language."
  }
}

Possible statuses:

likely_ai
possibly_ai
likely_human
insufficient_evidence
not_supported

The exact detector/model should be selected after inspecting the existing project and available dependencies.

Important limitation

AI-text detection should be treated as an estimation, not proof.

Even Google's own SynthID documentation describes watermarking as complementary rather than a universal solution, and its text watermarking works better on longer generated responses.

7. Feature 2 — AI-Generated Image/Media Detection

This part should not immediately send every image to an expensive detector.

That would be inefficient.

Instead:

All media
    ↓
Media Triage
    ↓
Is this worth analyzing?
    ↓
YES ──→ Deep AI-media analysis
NO  ──→ Skip / low priority
8. Media Triage

The first stage should be cheap.

Check:

A. File type
jpg
jpeg
png
webp
gif
mp4
etc.
B. Metadata

Look for:

EXIF
software information
creation information
camera information
editing software
provenance metadata
C. C2PA / Content Credentials

Check whether the media contains Content Credentials.

C2PA is an open provenance standard that can record information about how an asset was created and modified. It is not itself a “truth detector.”

Current C2PA guidance also supports machine-readable information describing whether content was generated, AI-modified, captured, or edited.

D. Known AI provenance

Check supported provenance signals where technically available.

For example, Google's SynthID embeds invisible watermarks into supported AI-generated media.

OpenAI's current verification tooling similarly checks supported images/audio for provenance signals including C2PA and SynthID.

9. Media Priority Score

Instead of:

Every image → AI detector

use something like:

media_priority_score =

provenance_signal
+ suspicious metadata
+ source/context
+ visual anomaly
+ claim importance
+ image reuse

For example:

Situation	Priority
Normal photograph from known news source	Low
Image has valid camera metadata	Low
Image has C2PA provenance	Low/Medium
Image has suspicious editing metadata	Medium
Viral image attached to controversial claim	High
Image appears synthetic	High
Important breaking-news image	High

Possible result:

But the system should distinguish:

AI-generated
AI-modified
Possibly AI-generated

Insufficient evidence

This is better than simply:

REAL
FAKE
11. Provenance vs AI Detection

This distinction needs to be explicitly documented in the project.

C2PA detected

Means:

There is verifiable provenance information associated with the asset.

It does not automatically mean:

The image is fake.

C2PA's own principles state that provenance systems are intended to verify assertions associated with content rather than make value judgments about whether that content is “good” or “bad.”

Similarly, OpenAI notes that detected provenance signals indicate origin but do not establish whether the content is accurate, unedited, legally owned, or correctly contextualized.

12. Feature 3 — Context / Truth Verification

This is arguably the most important feature.

The question isn't:

“Was AI used?”

The question is:

“Does the content appear to be true in the context in which it is being presented?”

13. Claim Extraction

First identify the actual claim.

Example post:

“COMSATS Islamabad has announced that all classes will remain suspended until Monday because of security concerns.”

The system should extract:

Entity:
COMSATS Islamabad

Claim:
Classes are suspended until Monday.

Reason:
Security concerns.

Time:
Current/upcoming period.

Instead of fact-checking the entire post as one giant block.

14. Evidence Retrieval

The system should then search for supporting/contradicting evidence.

Potential sources:

Primary sources

Highest priority:

official university website
official government website
official university social-media account
official department account
official press release
Secondary sources
reputable news organizations
established publications
multiple independent sources
Tertiary sources
other social-media posts
blogs
forums

The source hierarchy should matter.

For example:

Official COMSATS announcement
        ↓
Very strong evidence

Random Facebook post
        ↓
Weak evidence

16. Verdict System

Do not use only:

TRUE
FALSE

Use:

SUPPORTED
CONTRADICTED
UNVERIFIED
MIXED
OUTDATED
Supported

Reliable evidence agrees with the claim.

Contradicted

Reliable evidence directly conflicts with the claim.

Unverified

There isn't enough reliable evidence.

Mixed

Some parts are supported while other parts conflict.

Outdated

The claim may have been true previously but is no longer current.

21. Do Not Create a Fake “Accuracy Score”

Avoid something like:

Authenticity = 87%

unless there is a carefully designed statistical model behind it.

Instead, show separate evidence dimensions.

Recommended:

AI Text:       Likely AI
AI Image:      Possibly AI
Context:       Supported
Evidence:      Strong

This is much more defensible.

23. Recommended Processing Strategy

Don't run everything synchronously every time a scan happens.

Better:

RUN SCAN
   ↓
Collect posts
   ↓
Clean + deduplicate
   ↓
Store posts
   ↓
Analyze new posts
   ├── Text analysis
   ├── Media triage
   ├── Media analysis if required
   └── Context verification
   ↓
Store results
   ↓
Dashboard

And importantly:

If post already analyzed:
    don't analyze again

unless the user explicitly requests re-analysis.

24. Efficiency Strategy
Cheap operations first
1. Text length
2. Language
3. Duplicate check
4. Metadata
5. Provenance
6. Simple heuristics

Then expensive operations:

7. AI text detector
8. AI image detector
9. Claim extraction
10. Evidence retrieval
11. LLM reasoning

This prevents the system from wasting resources.
